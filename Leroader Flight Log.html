    Features

    • On: visible tab reloads every 30s. Off: nothing runs.
    • Interval from 5s to 5h by slider, −/+ and quick chips.
    • Site and page rules from the popup or by tapping an open tab.
    • Scope: visible tab, all tabs, or rules only.
    • Countdown badge, optional hard reload, Alt+Shift+R toggle.
    • Dark settings page in its own tab, thin scrollbars, phone-width layout.

    Known limits

    • Discarded (sleeping) tabs are skipped.
    • brave:// and other browser pages cannot be reloaded by any extension.
    • Screenshots were never looked at because the image tool failed. Layout was verified by measurement.
    Debrief

    What this run teaches

    These are observations from reading the log, not claims from the agent.

    Scale the proof to the ask.

    The request was a personal tool. The agent built a 292-line, 30-check browser test and spent about 68% of the run in the verify-and-debug phase. The user said so at T+25:56. A one-line "how much testing do you want?" at the start would have cut most of that.

    Human nudges were short and decisive.

    Three short messages, under 50 words in total, supplied the repo, challenged a silent retry loop, and stopped the polishing. Each one changed what the agent did next.

    Fail loudly in tests.

    The review of a swallowed-error wait loop led to a helper that reports how long the race lasted: 164 to 611 ms between the worker attaching and the extension APIs existing.

    Measure when you cannot see.

    With the vision tool down, the agent printed icon pixels as ASCII and measured popup height in the DOM. The popup was brought to 561px against a 600px limit without one screenshot.

    Check summaries against the code.

    The final message said the extension was "about 900 lines". Counting background, popup, options, shared and UI scripts gives 1,192 lines of JavaScript. Small, but the kind of drift worth catching.
